# 首页 UGUI 搭建说明

## 资源与入口

- `Assets/Prefabs/UI/MainMenu.prefab`：整个首页的可复用 UGUI 预制体。
- `Assets/Scenes/MainMenu.unity`：示例入口场景，通过 MainMenuBootstrap 实例化预制体。
- `Assets/Scenes/Preview/MainMenuPreview.unity`：直接摆放预制体的编辑预览场景，不进入 Play 也可查看层级和布局。
- `Assets/Scripts/UI/MainMenu/`：首页显示、按钮选择、运行时生成入口。
- `Assets/Scripts/UI/Common/UIFrameAnimation.cs`：可复用 Image 帧动画。
- `Assets/Art/UI/MainMenu/`：从用户图集中拆出的独立 PNG，保留透明通道。
- `ArtSource/MainMenu/`：八张原图与切分记录 slices.json，不参与游戏构建。
- `Tools/prepare_main_menu_art.py`：可重跑的图集切分脚本，需要 Pillow 和 NumPy；剪贴板原图不在时读取已保存副本。
- `Assets/Editor/UI/MainMenuBuilder.cs`：编辑器重建与后台离屏截图工具，不进入运行时构建。
- `Artifacts/MainMenu/`：Unity 实际渲染截图和验证结果。

首页的开始游戏、选关发出事件供后续流程接入；设置现已接入 SharedModal 共用弹窗，详见《统一弹窗搭建说明》。退出在 Windows 构建中退出应用，编辑器中仅发出事件。

## 首页结构

```text
MainMenu（Canvas + CanvasScaler + GraphicRaycaster + MainMenuView）
└─ Composition（固定参考比例，RectMask2D）
   ├─ Sky：透明背景的统一底色
   ├─ DistantFactory：用户远景
   ├─ LeftShade：辅助透明遮罩，保证标题/菜单可读
   ├─ ForegroundSteelwork：用户前景钢架
   ├─ GameTitle：用户提供的标题图
   ├─ ChargingStation：Image + 四帧动画
   ├─ Robot：Image + 四帧动画
   ├─ SelectionArrow：当前操作指示符
   ├─ StartGame / LevelSelect / Settings / QuitGame
   │  └─ 独立文字 Image
   ├─ ControlHint：用户像素文字提示
   └─ HintRule：底部横线
```

Canvas 为 Screen Space Overlay，参考分辨率与用户预览一致，1672×941；CanvasScaler 使用 Expand，全部元素共同缩放、不单独拉伸背景或角色。在其他宽高比下维持内容比例并增加边距，Composition 遮罩裁掉溢出画面的装饰。

本页面是屏幕空间 UI，不等同于关卡世界的 32 PPU 地块。纹理导入 PPU 统一为 32、Point 过滤、无压缩、无 Mipmap，但 UI 大小由 RectTransform 决定。正式低分辨率母版和整数倍率规范仍供后续关卡资产执行。

用户各图集与预览图并非完全同构：标题图集含额外机械支架，按钮文字更厚，远景缺少不透明天空和左上高楼层。因此采用实际提供的标题/按钮/文字，补统一底色与辅助暗遮罩；根据实际前景校准远景和平台位置。原图均保留，没有从整张预览图烘焙假按钮。

## 动画与输入

充电站由低电量到高电量四帧循环，单帧约 0.55～0.7 秒；机器人四帧待机包含头部倾斜和眨眼，眨眼帧较短。两套动画分别计时，并使用同一组内公共裁剪区域，保持脚底和底座稳定。无需 Animator Controller，可在 UIFrameAnimation Inspector 修改帧和时长。

动画使用 unscaledDeltaTime，因此以后游戏暂停时首页动画仍可播放。组件关闭后再启用从第一帧开始。帧尺寸由容器决定，不在每次换帧时调用 SetNativeSize。

Button 使用真正的 UGUI 点击和 EventSystem。鼠标进入按钮同步选择状态；方向键上下切换，Submit 输入确认。青色外框和箭头一起移动。开始游戏文字额外生成普通态，保留原图，避免选中其他按钮时首页第一按钮仍固定显示青色。

## 代码生成与事件接口

MainMenuBootstrap 的序列化 menuPrefab 引用已经连接。打开 MainMenu.unity 后进入 Play，会生成首页；编辑模式场景内不放重复的 Canvas。

其他场景也可以把该预制体拖给自己的序列化字段，在已有 EventSystem 的情况下直接生成：

```csharp
using Rustbound.UI;
using UnityEngine;

public sealed class ScreenCoordinator : MonoBehaviour
{
    [SerializeField] private MainMenuView mainMenuPrefab;
    private MainMenuView menu;

    private void Start()
    {
        menu = Instantiate(mainMenuPrefab);
        menu.LevelSelectRequested.AddListener(OpenLevelSelect);
        menu.SettingsRequested.AddListener(OpenSettings);
    }

    private void OnDestroy()
    {
        if (menu == null) return;
        menu.LevelSelectRequested.RemoveListener(OpenLevelSelect);
        menu.SettingsRequested.RemoveListener(OpenSettings);
    }

    private void OpenLevelSelect() { /* 后续生成选关预制体 */ }
    private void OpenSettings() { /* 后续生成设置预制体 */ }
}
```

四个事件为 StartGameRequested、LevelSelectRequested、SettingsRequested、QuitRequested。页面不自行拼接场景名字，后续由导航协调组件连接页面和关卡流程。

## 重建与截图

原项目内可从菜单 `Rustbound → UI → Rebuild Main Menu` 重建序列化预制体与入口场景；重建会替换生成资产，应先保存自己对首页的修改。当前默认不自动执行重建，不因为项目打开而切换用户场景。

本次使用 `.work/UnityMainMenu` 独立后台工程和本机已有 Unity 2022.3；仅复制本地依赖，原项目 Packages、SampleScene 和用户前台窗口不受构建工具操作。截图通过 Camera + RenderTexture 离屏渲染，来自真实 UGUI，不是 Python 合成图。

后台工具入口为 `Rustbound.EditorTools.MainMenuBuilder.BuildAndCapture`，配合 `-batchmode` 和 `-jumpOutput`。不要对同一个已打开的工程启动第二个 Unity；使用独立工程并等待其退出。独立工程为临时工作副本，正式资源以本项目 Assets 为准。

验证内容：C# 编译、预制体和 Sprite 引用、四按钮事件分别触发、禁用/启用不重复订阅、选择状态切换、两组动画时间线推进、两个不同帧的实际截图。结果见 Artifacts/MainMenu/validation.txt；尚未进行后续关卡和其他页面测试。

本次以上检查已通过。正式资产同步后又运行 `Tools/verify_main_menu_assets.py`，确认预制体、入口场景、编辑预览场景的 GUID 引用都能在原项目中解析，截图差异仅出现在机器人与充电站区域。
