# 《锈境：能源重启》课程设计方案

最新关卡结构：原三关内容整合到前两关，第三关改为四层纵向攀登塔，通关点高度 19.5 单位；平台采用子模块碰撞体、父级组合碰撞器和平台效应器。充电站数量为 1/2/1，水晶数量为 13/17/10，拾取物放大并浮动。具体路线与编辑位置见 [三关整合与纵向地图](三关整合与纵向地图.md)，该规格优先于旧三关布局表。

状态：主菜单、弹窗、选关和游戏 HUD 已实现 UGUI；三个独立玩法场景、可编辑地图预制体、物理碰撞、电池供电、可选水晶、组件事件和场景跳转已实现。地图编辑以 [地图编辑与机关组件说明](地图编辑与机关组件说明.md) 为当前规格。界面详见 [界面设计与生图指南](界面设计与生图指南.md)。

## 1. 项目目标与现有环境

使用 Unity 制作 Windows 单机 2D 横向平台闯关游戏，适用于游戏软件开发课程设计。玩家操控维修机器人，通过跳跃、冲刺、躲避机关和拾取道具，穿过废弃机械设施，重启能源终端。

目标是完成一款三个小而精关卡的小游戏，首轮探索与重试约 4～6 分钟，具备完整流程，能在答辩中解释组件化、状态机、事件通信、数据配置和存档思想。优先保证操作稳定、关卡可通关、像素风一致。具体坐标、距离和机关详见 [关卡场景搭建设计](关卡场景搭建设计.md)。

项目检查结果：

- Unity：2022.3.62f3c1。
- 渲染管线：Built-in，GraphicsSettings 未指定自定义 Render Pipeline。
- 已有 2D Feature、Tilemap、2D Animation、Pixel Perfect 5.1.0、UGUI、TextMeshPro。
- 当前使用旧版 Input Manager；本方案沿用该输入方式，输入访问集中在一个组件。
- 当前已有 MainMenu、Level01、Level02、Level03 场景及对应 UI / 世界组件。

## 2. 游戏定位与范围

采用手动控制的固定关卡平台跳跃，正常难度、有检查点、危险清晰可见。废土题材主要通过锈蚀金属、废弃管道、断电机械和稀疏黄沙表达。

课程版本包含：

- 3 个固定关卡；每关 2～3 段挑战，1～2 个检查点。
- 移动、单次跳跃、冲刺、死亡与检查点复活。
- 地形、尖刺/废料危险区、移动平台、巡逻机器人。
- 必经路线机关使用电池供电；水晶为可选收集，另有一次性护盾、临时跳跃增强。
- 主菜单、选关、暂停、结算、关卡解锁与最佳成绩。
- 简单动画、音效和像素特效。

本期仅实现电池数量库存，不制作物品格背包；不包含战斗、Boss、技能树、随机生成、联网和开放世界。后续若有余力，优先增加一个组合关卡或隐藏收集点。

## 3. 操作与规则

| 操作 | 默认输入 | 行为 |
| --- | --- | --- |
| 左右移动 | A/D 或左右方向键 | 水平移动与朝向切换 |
| 跳跃 | Space | 地面跳跃；允许短暂离地宽限与提前输入缓存 |
| 冲刺 | Shift | 按朝向水平冲刺，有冷却，不提供无敌 |
| 交互 | E | 在范围内操作拉杆或墙面按钮；压板由箱子重量自动触发 |
| 暂停 | Esc | 暂停/继续，结算与主菜单不响应游戏暂停 |

起始参数用于灰盒调试，并非最终平衡值：移动速度 4.5 单位/秒；普通跳跃约 2.2 单位高；冲刺速度 10 单位/秒、持续 0.15 秒、冷却 1.2 秒；离地宽限 0.10 秒、跳跃缓存 0.10 秒。跳跃增强使起跳速度为基础值的 1.2 倍，持续 6 秒；实际高度由重力与碰撞共同决定。

冲刺每次离地最多一次，落地重置空中次数，冷却继续计时。本轮关卡设计明确冲刺只改变水平速度，竖向速度与重力继续生效；首轮重力加速度 28 U/s²、起跳速度约 11.10 U/s。死亡或复活清理冲刺状态与速度，避免残留。普通同高跳跃理论约 3.57 U，加入一次冲刺约 4.39 U；普通缺口建议 2 U，冲刺缺口 3～3.25 U，待灰盒实测调整。

无生命值与攻击系统。触碰敌人/尖刺即死亡；有护盾时消耗护盾并获得 0.8 秒接触保护，避免同一次重叠持续触发死亡。跌出地图属于必死条件，不由护盾抵挡。

死亡后短暂停顿并打开失败界面，玩家选择“检查点重试”或“重新开始本关”；尚无检查点时显示“起点重试”。检查点重试清空速度、护盾、跳跃增强、冲刺状态和输入缓存，回到安全位置。死亡表现期间继续计时，失败面板、暂停和设置期间停止计时；重试恢复。本次用户要求的失败界面替代早期自动复活流程。

机器人使用内置电量驱动机关，初始 20/100，必须通过 E 使用地图上的充电器补充，默认每个机关首次消耗 40 电量并保持供电；终点不检查剩余电量。水晶（旧代码名 Fragment）是可选收集，不影响通关。HUD 显示电量百分比/数值及水晶收集比例，胜利页显示充电器首次使用数/总数和水晶比例。第一关 2 充电器 / 8 水晶，第二关 3 / 10，第三关 3 / 12。详见 [机器人动画与充电使用说明](机器人动画与充电使用说明.md)。

## 4. 关卡设计

| 关卡 | 场景主题 | 教学和挑战 | 建议长度 |
| --- | --- | --- | --- |
| 01 废料回收区 | 铁板、废料箱、断裂管道 | 普通跳、推箱压板开门、检查点、同高冲刺跳 | 32 单位 |
| 02 废弃运输线 | 输送结构、悬空铁架、起重残骸 | 拉杆启动水平平台、检查点、冲刺、一个巡逻机器人与护盾 | 36 单位 |
| 03 能源核心站 | 反应堆外壳、检修通道、青色能源管 | 推箱和按钮两路供电、上升冲刺跳、组合出口、可选跳跃增强 | 36.5 单位 |

流程遵循“安全展示 → 单独练习 → 少量组合”。首次遇到道具或机关时，附近有落脚平台与简短中文提示。普通通关路径不依赖限时道具；道具帮助走捷径或拿额外碎片。

移动平台起步只做水平往返，玩家站在平台上时应用平台位移增量，不通过反复改变玩家父节点实现搭载。跳离即停止继承位移，复活解除搭载状态。

敌人只在两个巡逻点之间往返，不追踪玩家。关卡必须检查平台接缝、冲刺撞墙、低顶跳跃和复活点落地安全。

## 5. 完整流程与界面

主菜单 → 选关 → 游戏关卡 → 通关结算 → 下一关/选关/主菜单；死亡进入失败面板，选择检查点重试或重开本关。主菜单和暂停页可进入设置，设置返回其来源页面。

首次仅解锁第一关。已解锁关卡可重复游玩。HUD 显示内置电量百分比/数值、水晶已拾取/总数、时间和冲刺冷却。暂停界面提供继续、重新开始和返回菜单；结算显示充电器使用、水晶、时间、死亡次数及下一关解锁状态。

每关保存最高收集数和最短通关时间，分别标注，避免让玩家误以为它们来自同一次游玩。死亡次数展示本次结果，不另外设计复杂评分公式。

界面外框、按钮装饰和图标采用像素风。当前固定中文标签使用用户提供的风格化文字图集；新增动态中文采用许可明确的字体。

**统一数字规范（已确认）**：选关页面及后续游戏中的全部数字，统一使用 `Assets/Art/UI/Modal` 中既有的 `Digit0`～`Digit9` 图集及 `SpriteNumberLabel` 组件。关卡编号、时间、收集数、死亡数、百分比、HUD、冷却数值等均由这套数字拼接；冒号、斜线、百分号与短横线复用同目录符号素材，小数点从既有冒号素材拆取，不使用其他数字字体或新图集中烘焙的样例数字。当前补齐了短横线以显示 `--:--`、`--/--`。该规则适用于后续所有页面和关卡。

选关页面固定三个关卡，首次仅第一关可进入。卡片在锁定、普通解锁、当前选中三个状态之间切换；青蓝描边仅出现在当前选中卡片。打开选关页时优先选中新解锁关卡，否则选中上次进入的关卡；玩家也可手动选择其他已解锁关卡。通过“进入关卡”后记录上次游玩关卡并清除新解锁提示。通过第 1、2 关依次解锁下一关，第 3 关不会产生额外关卡。进度与各关独立最佳成绩以版本化 JSON 保存到 PlayerPrefs，UI 通过事件将关卡编号交给后续游戏流程加载。

## 6. 程序结构

按职责分组，不搭建庞大框架；不用 ECS、依赖注入容器或通用事件总线。场景入口负责连接引用，常规依赖由 Inspector 指定，避免每帧查找对象。

| 模块 | 主要组件 | 职责 |
| --- | --- | --- |
| 游戏流程 | GameFlowController | Playing/Paused/Failed/Respawning/Completed 状态；失败、复活与结算编排 |
| 场景切换 | SceneFlowController | 菜单、选关、关卡切换；切换前恢复 Time.timeScale |
| 玩家 | PlayerInputReader、PlayerMotor、PlayerStateMachine | 采样输入；Rigidbody2D 移动与地面检测；Normal/Dashing/Dead 状态 |
| 玩家效果 | PlayerEffects、PlayerDamageReceiver | 护盾、计时增益、危险接触处理 |
| 关卡 | LevelController、Checkpoint、ExitTrigger | 出生点、检查点、安全复活位置、终点 |
| 世界对象 | Hazard、PatrolEnemy、MovingPlatform | 危险、敌人巡逻、平台运动 |
| 交互机关 | PushableCrate、WeightPlate、LeverSwitch、WallButton、SignalLatch、SignalRelay、GateController | 限速推箱、重量信号、E交互、解谜锁存、两路AND、门碰撞与表现；复用预制体 |
| 收集 | Pickup、PickupDefinition | 拾取检测、效果配置、销毁/隐藏策略 |
| 统计 | RunStats | 当前关卡时间、碎片数、死亡数 |
| 存档 | SaveService、SaveData | JSON 序列化、关卡解锁与最佳成绩 |
| 表现 | PlayerAnimation、CameraFollow、HUD、菜单/暂停/胜利/失败面板 | 动画、相机、显示与按钮行为 |
| 设置 | SettingsService、SettingsPanel | 音乐/音效音量、全屏、设置持久化；记录返回来源；不删除关卡进度 |

`PlayerStateMachine` 管理互斥行为，护盾与跳跃增强由 `PlayerEffects` 管理，因为它们可以与移动或冲刺同时存在。第一版用枚举与集中转换函数即可，状态数量增长时才拆成状态类。

输入在 Update 采样并记录跳跃/冲刺请求，在 FixedUpdate 消费请求并更新物理。动画订阅状态或读取只读运动数据，动画结束不作为物理行为唯一依据。暂停/结算会阻断玩家输入。

### 6.1 事件与数据

以实例 C# 事件通知：`PlayerDied`、`CheckpointActivated`、`PickupCollected`、`StatsChanged`、`LevelCompleted`。事件发出者报告事实，接收者执行各自工作。

例如收集物只请求拾取并报告 ID 与效果；统计模块更新碎片数；HUD 收到 StatsChanged 后刷新。HUD 不写玩家速度，玩家也不直接操作 UI 文本。

GameFlowController 负责死亡事件后的流程切换，RunStats 记录死亡次数。所有订阅在 OnEnable/OnDisable 成对处理；避免场景重载后重复订阅。

`ScriptableObject` 保存 `PlayerConfig`（移动/跳跃/冲刺参数）、`PickupDefinition`（类型/图标/时长/倍率）、`LevelDefinition`（稳定关卡 ID/场景名/展示名）。运行时效果和计时器不写回配置资产。

道具实现四种类型：电池、水晶、护盾、跳跃增强。重复护盾保持一层；重复跳跃增强刷新时长，倍率不叠加。增强到期恢复基础配置，避免反复乘除造成漂移。

### 6.2 复活与存档边界

- 本次关卡中已收集的碎片保持已收集，避免死亡刷分；以关卡内唯一 Pickup ID 记录。
- 护盾/跳跃增强在死亡后消失，拾取点本次运行不重生；普通路线必须不依赖它们。
- 敌人与移动平台复活时回到初始位置，解除玩家搭载关系；检查点周围保留安全空间。
- “重新开始”重置本次关卡全部对象、计时、收集状态和死亡数，回到关卡初始出生点。
- 通关时更新解锁和最佳成绩，进入关卡时更新上次关卡；不保存中途位置和临时道具。
- 当前实现为版本化 JSON 存在 PlayerPrefs，由 LevelProgressRepository 管理；缺失或损坏时使用默认数据，不额外建设另一套进度存储。
- 检查点重试保留本次已锁存的供电/解谜标记；箱子回到安全初始位置，门和平台的启用状态按锁存信号恢复。整关重开才清空锁存标记。
- 进度与最佳成绩跨运行保存；稳定关卡 ID 不依赖场景在 Build Settings 的序号。

## 7. Unity 场景组织

建议使用 MainMenu 场景与 Level01/Level02/Level03 场景。选关作为菜单面板；结果与暂停作为关卡 Canvas 面板。不增加专门的结算场景。

```text
Level01
├─ Systems：流程、关卡、统计、场景切换
├─ Grid
│  ├─ Ground：可碰撞地形 Tilemap
│  ├─ BackDecoration：不可碰撞后景
│  └─ FrontDecoration：不遮挡危险和落点的前景
├─ World：机关、敌人、检查点、收集物、终点
├─ Player：物理根节点 + Visual 子节点
├─ Main Camera：正交相机、跟随组件、Pixel Perfect Camera
└─ Canvas：HUD、暂停、结算
```

建议脚本目录：Assets/Scripts/{Core,Player,World,Items,UI,Data}；素材 Assets/Art/Pixel/{Characters,Tiles,Props,Backgrounds,UI,Effects}；配置 Assets/Data；预制体 Assets/Prefabs；正式场景 Assets/Scenes。

本版地形逐块拼接 SpriteRenderer，每段使用连续 BoxCollider2D + Static Rigidbody2D，避免分块碰撞接缝。移动平台独立使用 Kinematic Rigidbody2D / MovePosition，搭载方式已通过真实物理验证。Layer 8..13 区分 WorldGround、WorldPlayer、WorldCrate、WorldPlatform、WorldHazard、WorldTrigger，地面检测检查地形、箱子与运输平台。背景不创建碰撞体。实际三关、预制体与运行入口见 [三关实现与运行说明](三关实现与运行说明.md)。

项目沿用 Built-in，以无光照精灵材质与预绘明暗表现机械体积；暂不切换 URP。相机只做水平跟随、少量垂直跟随与关卡边界限制，不引入震屏或动态缩放。

## 8. 美术方向

统一像素密度 32 PPU，参考画面 640×360。1 单位地块是 32×32；角色帧 32×48。低饱和暖灰/锈橙构成环境，青色标记玩家与能源，危险用红色或黄黑形状标识。背景低对比，地面顶边和危险轮廓清楚。

详细规范见 [像素美术规范](像素美术规范.md)，生成提示见 [美术生成提示词](美术生成提示词.md)。界面布局与提示词入口见 [界面设计与生图指南](界面设计与生图指南.md)。同 PPU 不等于所有图片同尺寸，应按世界尺度设置画布，并禁止随意缩放精灵。

## 9. 实施顺序与验收

| 阶段 | 交付 | 验收条件 |
| --- | --- | --- |
| 1 灰盒闭环 | 一个简单测试关卡 | 移动跳跃稳定；危险死亡；检查点复活；终点结算 |
| 2 完整流程 | 菜单、选关、暂停、存档 | 首次锁关；通关解锁；重启保留进度；暂停返回菜单不会卡住时间 |
| 3 玩法扩展 | 冲刺、两种效果、敌人、平台 | 冷却正确；效果到期恢复；平台搭载稳定；复活无残留状态 |
| 4 美术样板 | 铁板地块、机器人站姿、道具、背景块 | 原生尺寸与 PPU 正确；整数倍显示像素均匀；无模糊边缘 |
| 5 关卡与表现 | 三关、基础动画与音效 | 普通路线不用道具也可通关；每关具有不同组合；危险清楚 |
| 6 课程交付 | Windows 构建、报告、演示说明 | 脱离编辑器运行；完整演示一次通关和进度保存 |

关键手工验证：暂停时道具和冷却不流逝；连续按跳跃/冲刺无卡死；冲刺撞墙不穿透；护盾在接触区只消耗一次；跌落必定复活；连续死亡后恢复重力；碎片不重复记分；移动平台复活后不带走玩家。

画面检查至少覆盖 1280×720、1920×1080 与非整数倍率窗口。非整数倍率允许黑边，不通过拉伸填满窗口。JSON 存档和效果计时等纯逻辑适合少量自动化测试，跳跃与平台搭载需要实际游玩验证。
