# 废土机械风像素美术规范

## 全项目数字资源约束

选关页与后续游戏全部数字统一复用 `Assets/Art/UI/Modal/Digit0`～`Digit9`，使用 `SpriteNumberLabel` 动态排版。冒号、斜线、百分号与短横线使用同目录配套符号。不得采用新素材中烘焙的样例数字，不为 HUD、计时、收集、冷却或其他页面引入第二套数字字体。固定中文可用用户提供的文字图集。

## 1. 统一尺度的定义

本项目每个 Unity 世界单位对应 32 个素材像素，即 PPU = 32。所有世界素材使用相同 PPU；精灵 Transform 的有效世界缩放保持 (1,1,1)，允许朝向使用 SpriteRenderer.flipX。

公式：世界宽度 = 原生素材像素宽度 / 32。像素画中的一个逻辑像素应对应最终 PNG 的一个像素，不能把放大的像素预览直接当成原生素材导入。

例如：32×32 地块为 1×1 单位；64×32 平台为 2×1 单位。两者纹理像素密度完全相同。64×64 图改成 Scale 0.5 虽然变成 1 单位，却使像素密度变为 64/单位，不符合规范。

同样的物体可以有不同外形，但不能出现角色每个色块占 4×4 原图像素、地形每个色块却占 1×1 像素的混合分辨率。AI 生图中的“像素风”可能出现这种问题，必须以最终低分辨率母版和同屏检查验收。

## 2. 画布规格

本轮场景批量素材采用统一图集：源图2048×2048、8×检查倍率，还原成256×256原生母版；8列×8行，每格32×32原生像素对应1×1世界单位。组件按实际大小占半格、一格或多格，切片后尺寸各不相同，PPU仍统一32。布局和提示词见 `ArtSource/Prompts/Scenes/场景素材生成提示词.md`。不得将2048检查图直接导入世界素材，也不得用缩放抵消像素密度。

尺寸含透明留白。下表世界尺寸表示整张画布的占用，不等同于碰撞体或物体可见轮廓。

| 素材 | 原生 PNG 尺寸 | 画布世界尺寸 | 要求 |
| --- | --- | --- | --- |
| 地形单块 | 32×32 | 1×1 | Tilemap 单元 1×1；接缝可拼接 |
| 维修机器人动画单帧 | 32×48 | 1×1.5 | 身体约 22～26×38～42 像素，脚底基线固定 |
| 巡逻机器人单帧 | 32×32 | 1×1 | 整套帧尺寸一致 |
| 能源碎片、道具图标 | 16×16 | 0.5×0.5 | 轮廓简洁，透明背景 |
| 尖刺/废料危险块 | 32×32 | 1×1 | 碰撞按有效危险区域设置 |
| 移动平台 | 64×32 | 2×1 | 可见铁板可只占上方 8～12 像素 |
| 检查点灯塔 | 32×64 | 1×2 | 底部枢轴，未激活/激活两态 |
| 出口能源终端 | 64×96 | 2×3 | 底部枢轴，终点触发区独立 |
| 大型装饰机械 | 64×64 或 96×96 | 2×2 或 3×3 | 用大画布表达大物体，禁止缩放补偿 |
| 远景模块 | 320×192 | 10×6 | 在原生像素网格绘制，按原尺寸拼接 |
| 粒子/冲刺特效帧 | 16×16 或 32×32 | 0.5×0.5 或 1×1 | 二值透明，少量颜色 |

角色全部帧固定画布与脚底锚点，不逐帧自动裁剪。平台碰撞与可见顶面对应；不要因为画布有透明空白就用整幅矩形碰撞。

首批地形只制作上沿左/中/右、填充、底部、独立平台等少量手动 Tile；验收重复拼接后再考虑 Rule Tile。

## 3. 风格、色板与可读性

正侧视、正交构图、无透视。机械造型采用矩形、粗管道、简洁关节和大面积金属板。每种材料通常用基础色、阴影色、亮面色三档表达，避免复杂金属反射和散点锈斑。统一左上方光源。

建议起始固定色板（共 16 色，可在样板阶段调整一次）：

| 用途 | 颜色 |
| --- | --- |
| 深色轮廓 | #171B22 |
| 极暗钢灰 | #272D35 |
| 暗钢灰 | #3D4650 |
| 中钢灰 | #606B73 |
| 亮钢灰 | #929D9F |
| 金属高光 | #C7CDC3 |
| 深锈色 | #633B32 |
| 锈棕 | #96533A |
| 锈橙 | #C17A43 |
| 沙土暗色 | #6D6652 |
| 沙土色 | #9B9472 |
| 沙色亮面 | #C9BD91 |
| 危险红 | #D65B4C |
| 警示黄 | #D6B85A |
| 能源青 | #4FB8B0 |
| 能源亮青 | #B3E4CD |

每张普通素材优先只取其中 4～8 色。透明不计入色板。玩家、道具和机关可用强调色；背景主要使用压暗的现有环境色，不另加一套细碎颜色。

表面使用连续色块；锈迹只保留几块能读出的轮廓，不均匀撒点。1 像素轮廓适合角色/道具，环境外轮廓避免堆成多条粗黑线。保留少量关键螺栓，不添加密集划痕。

地面顶边、敌人和危险比背景有更明显的明度差。安全/危险不仅靠红青区分，还要依靠尖刺形状、灯塔轮廓与符号。背景工厂使用暗轮廓，无密集灯光；远景表现距离靠色块与轮廓，不靠缩小其 Transform。

## 4. 生图与算法转换路线

推荐“简洁原图 → 定义物体尺度 → 低分辨率母版 → 色板量化 → 手工检查”。直接请求原生像素图可作另一条试验路线，但模型不能保证准确画布、统一像素格、精确十六进制颜色或无缝拼接。

### 4.1 生成阶段

每次生成优先只包含一个独立对象，正侧视，清晰轮廓，简单平涂。独立角色、道具和装饰请求真实透明背景；不要请求绘制棋盘格假透明。背景单独生成。

本次场景模块按用户要求采用明确网格的多对象图集，优先执行 Scenes 目录中逐件占格规格；上述单对象建议主要用于角色样板或失败重生某一组件。

高分辨率图只是素材来源，不是正式游戏图。提示中同时声明目标原生尺寸与 PPU，要求构造简单且在目标尺寸下可读。像素块应等大、边缘落在均匀网格上，不混合细腻写实区域与粗像素区域。

先做一个机器人站姿、一块铁板、一件道具、一块远景作为样板，统一后再扩展。首轮不批量生成动作表，避免角色外形和脚底位置在不同帧漂移。

### 4.2 转换阶段

用户已允许使用图像算法规范化生成图，后续可用 Pillow 等图像处理工具执行以下步骤；本次仅制定流程，未运行处理。

1. 读取 RGBA 图，检查真实 alpha；裁去来源图多余外边，但记录锚点。不要对每个动画帧独立紧裁。
2. 按预定可见尺寸等比缩小对象，居中/底部对齐到目标透明画布，禁止拉伸或随机填满整张画布。
3. 若输入为高分辨率平涂图，先以 AREA/BOX 类面积采样缩到目标尺度，再限制到固定色板；面积采样是为了汇总色块，不直接把临时抗锯齿结果当成成品。
4. 若输入已经是规整且整数倍放大的像素图，按已确认的网格相位与倍率还原；可用块内主色采样。只有已经对齐网格时才用 nearest 缩小，避免丢失线条。
5. RGB 映射到上述有限色板，默认禁用抖动；透明边使用 alpha 阈值生成 0/255 二值 alpha。颜色统计忽略透明像素，处理半透明边时避免混入背景颜色。
6. 人工检查眼睛、脚底、轮廓连通性、断裂线、单像素噪点；必要时修像素或重生更简单的原图。量化不能自动修好结构。
7. 正式资产保存为原生尺寸 PNG；若需要 4×/8×检查图，单独导出 nearest 整数倍预览，不把预览图放进正式资产目录。

不要直接把任意复杂图用 nearest 缩小就认为变成了合格像素画；它可能保留噪点，也可能漏采样细线。固定色板与低分辨率并不能保证轮廓质量。

地块最后需检查 3×3 或更大的重复排列：横向顶边一致，无缝隙、孤立亮点或重复后形成突兀条纹。无缝性由边缘像素约束和检查决定，不仅依赖提示词。

## 5. Unity 导入与显示

以下针对当前 Built-in + Pixel Perfect 5.1.0。已核对本项目包内 Documentation~/index.md。

| 设置 | 约定 |
| --- | --- |
| Texture Type | Sprite (2D and UI) |
| Pixels Per Unit | 32，所有世界素材一致 |
| Filter Mode | Point (no filter) |
| Compression | None；平台覆盖设置同样检查 |
| Generate Mip Maps | 关闭 |
| Wrap Mode | Clamp；背景第一版通过模块拼接而非依赖纹理 Repeat |
| Max Size | 不低于原文件最长边，避免 Unity 自动缩小母版 |
| Sprite Mesh | Full Rect 作为起步设置 |
| Pivot | 角色/灯塔/终端使用固定底部锚点，其余按用途设置 |

Tilemap Grid Cell Size = (1,1,0)，常规地块移动对齐 1 单位。单像素装饰摆放步长 1/32 = 0.03125 单位。角色与移动平台物理位置不强制逐像素取整，否则会影响碰撞与速度。

Pixel Perfect Camera：Assets PPU = 32；Reference Resolution = 640×360；起步启用 Upscale Render Texture，Crop Frame 的 X/Y 均启用，Stretch Fill 关闭。该模式下 Pixel Snapping 不可同时启用，不把两个选项都写成“必开”。相机跟随逻辑不反复写正交尺寸，避免与 Pixel Perfect Camera 冲突。

参考画面为 20×11.25 世界单位。1280×720 为 2×显示，1920×1080 为 3×显示。非整数倍率窗口允许居中黑边，禁止非整数 Stretch Fill。实际构建需用相机预览与截屏验证每个源像素呈相同大小方块。

背景保持 PPU=32 和有效缩放=1；如需填大区域，应拼接或生成更大母版。第一版背景随关卡排列；有余力才增加不缩放素材的视差位移，位移显示仍遵循像素渲染。

中文正文可使用独立的高分辨率 UI Canvas；世界素材与像素图标严格执行像素规范。图标若跟随 Canvas 缩放，也应整数倍显示并保持 Point 采样，字体清晰度与世界 PPU 分开验收。

## 6. 验收标准与目录

- 尺寸精确、PPU 一致、有效缩放为 1。
- 无写实渐变、密集噪点、半透明毛边；正式素材颜色属于批准色板。
- 角色所有帧画布/枢轴/脚底一致，轮廓不跳动。
- 危险、可站立顶面与碰撞体吻合，背景不会被误认为平台。
- 同屏中角色、地块、道具的单像素方块相同大小。
- 重复地块无明显接缝；远景缩放不破坏像素密度。
- 1280×720、1920×1080 与非整数倍窗口中均无拉伸或滤波模糊。

生成原图和中间产物放在 ArtSource/，不放进 Assets 参与构建。原生正式素材放在 Assets/Art/Pixel/。每批记录提示词、来源、目标画布、转换参数与文件名，便于复现。

参考：[Unity 2D Pixel Perfect 文档](https://docs.unity.cn/Packages/com.unity.2d.pixel-perfect%402.1/manual/index.html)。具体选项以本项目 5.1.0 包内文档为准。
